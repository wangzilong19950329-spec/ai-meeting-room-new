## 3. 本轮实现架构

### 3.1 数据采集

新增：

- `src/main/java/com/aimeeting/room/service/EastmoneyMarketDataService.java`

职责：

- 实时行情与分级资金流。
- 个股详情、行业、当前估值。
- 日/周/月 K 线。
- 最近 5 日分钟走势与 VWAP。

- 公司公告列表。

必需数据：

必需数据缺失时不允许生成预测。估值、财务、公告、分钟线等目前属于可选数据，失败时降低证据完整度，但不会阻塞技术预测。

### 3.2 本地计算指标

系统不再要求模型猜技术指标，以下指标由 Java 基于 K 线确定性计算：

- MA5 / MA10 / MA20 / MA60

- RSI14
- ATR14
- BOLL20
- OBV
- 20 日历史波动率
- 5/20 日收益率
- 20 日支撑/压力
- 相对市场基准强弱

关键金额与比例同时放入 `marketData.anchorFacts`：

- `changePercent`
- `amountYuan`
- `turnoverPercent`
- `volumeRatio`
- `mainInflowYuan`
- `mainInflowRatioPercent`
- 本地技术指标

模型提示词要求原样引用锚点，禁止自行进行金额单位换算或重新计算资金占比。

### 3.3 DeepSeek 结构化预测

主要入口：

- `src/main/java/com/aimeeting/room/service/StockWatchTechnicalAnalysisService.java`

日内分析要求：

- `T1`
- `T5`

周度分析要求：

- `W1`

月度分析要求：

- `M1`

每个预测字段：

```text
horizon
direction: UP / DOWN / SIDEWAYS
probability: 0-1
targetLow
targetHigh
expectedReturnLow
expectedReturnHigh
invalidationPrice
rationale
```

方向统一定义：

- 到期收益 `>= +1%`：`UP`
- 到期收益 `<= -1%`：`DOWN`
- 其他：`SIDEWAYS`

系统会检查当前周期要求的 horizon 是否齐全、目标区间是否合法。缺 T1/T5/W1/M1 时在同一会话要求重新输出完整 JSON；仍不完整则保存 ERROR 分析，不保存半截预测。

`expectedReturnLow/High` 不信任模型结果，落库时由程序使用 `target/sourcePrice` 重新计算。

## 5. 最高优先级未完成项

### P0：预测基准日期必须改成行情交易日

当前 `StockWatchTechnicalAnalysisService` 保存预测时使用：

```java
now.toLocalDate()
```

但本次真实输入的东财行情日期是 `2026-06-18`，任务实际运行日是 `2026-06-19`。因此记录 `1/2` 的 `forecast_date` 为 `6/19`，而预测起点数据来自 `6/18`。

这会导致 T1 评估错位：系统会找 `6/19` 之后的第一个交易日，而正确口径应是行情源 `6/18` 之后的第一个交易日。

建议改法：

1. 从 `quote.timestamp` 解析 `sourceTradeDate`。
2. `StockWatchPrediction.forecastDate` 改存 `sourceTradeDate`。
3. 分析表可新增或在快照中明确保留 `sourceTradeDate/sourceQuoteTimestamp`。
4. 如果 `sourceTradeDate < 当前最近交易日`，UI 标记“行情快照滞后”。
5. 是否允许使用滞后行情生成预测需要明确策略：建议允许人工运行，但必须显示滞后；自动调度遇到过旧快照应跳过。
6. 修复后，现有预测 `id=1/2` 建议删除重跑，避免污染准确率统计。

在这个问题修复前，不要把预测命中率当成可靠指标。
