# 未来30分钟走势预测MVP

日期：2026-10-05；实施验证：2026-10-06。状态：代码及控制验证完成，真实窗口待试点。用户在收到缩减方案后回复“继续吧”，本轮仅推进以下 M30 MVP，不实施完整持仓助手或原79项修复。未新增业务表或迁移，未调用模型。结果见[实施验证记录](stock-watch-intraday-30m-mvp-verification-2026-10-06.md)。

## 1. 当前目标

Goal Contract v2：先验证“现有DeepSeek分析多给一份未来30分钟预测，是否及时、是否有增量”，不先建设完整持仓风险助手。上一版方案留作后续参考，原bug清单不删除，但不把79项修复、57项新增功能全列为这个MVP的前置。

首版只做三件事：同次模型回复增加M30字段；现有分析详情显示预测和有效期；只读脚本复盘未来30分钟价格。验证成功后才决定自动评分、数据库表、风险提醒或持仓功能。

## 2. 实施前已核对的代码边界

- 技术分析的默认scan interval是1800000ms，采用fixedDelay；不是保证每股准点30分钟更新。`StockWatchTechnicalAnalysisService.java:229-264`、`application.yml:170-173`。
- DAY提示词说30分钟级别分析，但目前要求的预测是T1/T5。`StockWatchTechnicalAnalysisService.java:1674-1700`。
- 旧预测normalizeHorizon只接T1/T5/W1/M1；直接往forecasts数组塞M30会被严格校验拒绝。`StockWatchPredictionService.java:93-115,509-521`。
- 新任务的request envelope/projection会冻结，原回复已有rawResponse存储；旧v6普通结论另经可信renderer。`StockWatchTechnicalAnalysisService.java:667-701,803-851,3331-3379,3438-3451,4022-4036`。
- 已有分钟接口，但VALID主要判断非空，endTime由时间加一分钟推得；还不能据此直接承诺完整路径评分。`StockQuoteService.java:128-208,259-290`。

这些是源码现状，不是实际部署、行情实时性或预测效果证明。

## 3. 预测合同

只试1-3只用户选定的普通沪深股票、DAY盘中任务，复用原分析频率，不新增模型调用、行情快扫描或自动交易。

服务器在请求准备前冻结：`asOfAt`（输入快照截点）、`quoteSourceAt`、`referencePrice`、`targetAt=asOfAt+30分钟`和`intradayForecastVersion=M30_MVP_V1`。数据不晚于asOfAt，报价身份/尺度及源年龄必须合格；不能用较旧报价源时间作为窗口起点，却把后来的行情也送给模型。

模型只新增独立的根对象，不混进旧T1/T5数组：

```json
{
  "intradayForecast": {
    "status": "PREDICTED",
    "direction": "DOWN",
    "targetLow": 9.80,
    "targetHigh": 9.95
  }
}
```

示例数值非真实预测。`targetLow/High`定义为**30分钟到期价格区间**，不是整个区间的最高/最低价。首版不预测精确逐分钟路线，不输出未校准的“70%准确概率”。方向为UP/DOWN；不能判断时输出ABSTAIN且方向/区间为空，页面显示“不明确”，不把它计为命中或丢掉。

asOfAt/targetAt由服务端提供，不能相信模型改写。新profile声明M30扩展，写入既有冻结请求JSON，仅对启用后新的合格任务生效；基础v6字段/旧prepared任务原样处理，不占用原方案的v7合同，不因开关变化对同一canonical事实再次提交。

M30缺失/非法单独标MISSING/INVALID，不把原本合格的T1/T5或已成功分析判失败，也不补调模型。页面经后端白名单解析只显示M30字段，不开放rawResponse，不改旧可信结论来源。

## 4. 时间与迟到

例：10:00冻结输入，预测窗固定为10:00-10:30；10:03发布后显示“有效至10:30，剩余27分钟”，不是改成10:03-10:33。过期结果只放历史，不当当前预测。

首版只处理同一连续交易时段内能完整容纳30分钟的窗口，跨午休/收盘、停牌或不支持标的不生成有效M30。盘后不能生成“下一交易日30分钟”替代品；T1/T5仍按原逻辑运行。

建议先冻结工程试验值：报价年龄不超过120秒，发布相对asOfAt不超过5分钟。它们是候选预算，不是已证明可达的SLO；超预算标STALE_INPUT/LATE，过targetAt为EXPIRED。模型/源不可用和旧事实重放同样保留状态；先测是否有足够及时样本，不以HTTP成功证明可用。

不以“下一次分析的价格”作30分钟终点：fixedDelay、多股排队和模型用时会使下一次晚于目标。评价必须取固定targetAt对应证据。

## 5. 最小存储、页面与复盘

**零新业务表，零业务schema迁移**：预测仍在已有rawResponse中，权威时间/profile/参考价在冻结request envelope中。后端按task关联解释M30，保留原analysis/task/raw数据，不把输出塞进输入快照或factHash。

现有分析详情增加一行：`M30实验预测 | 偏弱 | 10:00-10:30 | 到期区间9.80-9.95 | 剩余27分钟`。另有不明确、缺失、过期/迟到、数据不可用状态；不新增工作台、持仓录入、通知或金额避损展示。

一个只读研究脚本按日期/试点标的/profile列出**所有已请求M30的任务机会**，包括拒答、失败、缺字段和迟到；关联原分析id/task id，读取原文、冻结时间与当日分钟数据。输出本地不可变研究JSON/CSV快照，不写业务评估或改历史成绩。试点计划槽位未触发任务的缺口另报，不假装请求覆盖100%。

端点描述结果：`frozenQuoteReturnPct=(endpointPrice/referencePrice-1)*100`。UP要求收益>0，DOWN要求<0，恰为0不算方向吻合；沿用符号口径，不借旧T1震荡阈值给30分钟打分。很小的符号吻合不等于扣费后可交易优势，另报告实际变动幅度。参见第8节：此口径不能称严格 asOfAt 后预测准确率。

到期价格选择规则先冻结：核验分钟时间含义与完成证据后，取时间不晚于targetAt、相差小于60秒的最后合格端点，保留真实evaluationPriceAt/价格尺度/源及抓取vintage；不是精确逐秒终价。没有合格端点则UNSCORABLE，不挪到后续价格或日收盘。脚本建议当日盘后运行，现有分钟接口ndays=1；未及时保存的历史窗口不能假定以后还能补回。

首版主统计只要求合格参考价和到期端点，**不要求整个30分钟路径完整**。若完整信号后分钟路径另外合格，可补报发布后至targetAt的最差收益，不能使用包含发布前价格的整根分钟low；路径未知只停此辅指标，不能填0。它是市场路径，不是实际避损。

研究快照按task+协议幂等，冻结预测、端点与结果；后续源修订另存带supersedes的研究revision，不静默改旧快照。评估脚本不依赖下轮模型，也不把人工运行脚本的时点当信号发布时间。

## 6. 快速验证怎么判

先测数据时间语义、源年龄和模型发布时延；不合格就先停在这一项，不扩建完整助手。默认1-3只股票，建议5-10个有效交易日、争取100-200条及时可评分记录，只作初筛，不是足够证明长期有效的样本量。

固定输出六项：请求/槽位覆盖；及时率与剩余有效时间；明确预测率（ABSTAIN单列）；及时且可评分方向命中；到期区间覆盖与区间宽度；可评分/缺失/迟到/失败分母。不要只展示成功预测。

同一可比较样本同时看“总预测上涨”“总预测下跌”和“沿用输入前30分钟涨跌方向”基线；缺历史30分钟端点只使动量对照不可比，不删除原样本。预测区间特别宽即使覆盖高也不视为准确。按股票/日期查看，重叠窗口不当独立证据。

阶段裁决：及时样本不足 -> 工程暂不可用；不优于简单基线 -> 暂无增量；初筛有增量 -> 延长新的前向验证，才考虑自动复盘/风险提醒。不能据100条或高命中宣称可实盘避损。

## 7. 本轮实施写集

1. 提示词/冻结扩展/profile：`StockWatchTechnicalAnalysisService`；按扩展版本解析，不改旧v6语义。
2. M30详情API投影与既有Vue分析详情；原预测页/T1/T5评估不变。
3. 一个只读复盘脚本及轻量协议/输出快照；必要时只补分钟端点资格适配，不重做行情架构。
4. 聚焦测试：旧任务重放、无二次提交、非法M30不伤旧成功、固定窗、午休/收盘、迟到/过期、ABSTAIN、缺端点和CSV分母。

不做新持仓表、事件/episode系统、可靠通知改造、30秒调度、概率校准、券商或自动订单。基础运行故障或源资格若阻断MVP，只定位并处理那条必需链，另获实施授权；原完整修复仍是后续backlog，不默认同时启动。

## 8. Challenge 后的实施边界

- 现有 expert 客户端开启联网；冻结 projection 不能证明模型只见过 asOfAt 前的信息。本轮不扩改 bridge，在请求和研究结果标记 `informationCutoffStatus=UNVERIFIED_WEB_SEARCH`。
- 报价源最多早120秒，冻结报价至 targetAt 的收益可能包含 asOfAt 前已发生的变化。研究结果为 `evaluationScope=FROZEN_QUOTE_TO_TARGET`、`DESCRIPTIVE_ONLY`；`strictAsOfDirectionAccuracy` 留空，不据之宣称严格未来30分钟的预测能力或实盘避损。
- 零schema条件下使用原 analysis.gmt_create 作为 `DB_INSERT_PROXY`，仅是入库代理，不是提交、接口响应、浏览器展示或用户收到时间。300秒预算只检验入库时延。新分析同步返回对象若没有入库时间，时效标UNKNOWN，重新读取历史后才有数据库代理时间。
- 数据源分钟完成性和时间语义未核验时，复盘必须 UNSCORABLE；本轮不自动把现有 trends2 的 VALID 当合格证据。
- 普通新建定时 DAY demand 不绑定 targetFact，仍用采集报价；异常需求及与其合并的定时需求会用 canonical fact.quote，它不保留新增供应商身份元数据。本轮不改 factHash/白名单，此类请求若无法核验身份就返回 INPUT_UNAVAILABLE/ABSTAIN，不换成较新的报价冒充原事实。
- 默认关闭：`STOCK_WATCH_M30_ENABLED=false`；`STOCK_WATCH_M30_SYMBOLS` 必须显式配置1-3只普通沪深股票，最多取前三个不同有效代码。两项为空/关闭时不追加提示词，不升级旧任务，不补调模型。开关需正常重启后生效。

启用示例（标的仅为格式示例，试点待用户确认）：`STOCK_WATCH_M30_ENABLED=true STOCK_WATCH_M30_SYMBOLS=002156.sz`。接入点为新 canonical task 的 prepare 前，权威请求进入 projectionJson 并一并计算其摘要；旧T1/T5与v6合同保持不变。

首轮可验证的是字段链路、响应时效、弃权/失败分母及端点描述性吻合。若要验证严格前向增量，下一步需要核验模型信息截止点并取得 asOfAt 起点行情，不能靠本轮描述统计代替。
