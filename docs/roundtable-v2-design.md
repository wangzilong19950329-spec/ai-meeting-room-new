# 圆桌会议流程 v2 设计

> 状态：设计已确认（2026-10-17），按切片实施中。
> 来源：三位 Claude agent（效率架构师、会议方法论专家、可靠性审计官）的圆桌会议，三票"有条件同意"，加上用户后续补充。

## 1. 初衷与优先级

- **初衷**：单一角色、单一视角、单次分析容易出错，也想得不深，很难发现真正有价值的信息。圆桌会议的作用是减少错误、逼出深度思考。
- **想要的产出**：经过多方深度论证的结论；哪些结论存在分歧、分歧的原因是什么。不是一句被强行收敛出来的"共识"。
- **优先级**：准确性 > token 消耗 > 速度。慢可以接受；只在本地运行，自己一个人用。

## 2. 流程（所有议题共用同一套阶段）

| 阶段 | 做什么 | 执行者 |
|---|---|---|
| P0 问题卡 | 列出标的或议题、asOf、展望期；把议题拆成 3–4 个子问题（驱动因素）；写明参照类（可选）；给出取证题清单。能判定结果的议题，由程序生成结果区间（按收益率定义） | 主持人（无搜索，temp 0.2，保持中立）+ 程序 |
| P1 事实底稿 | 按三级取证逐题取证，结果写入会议级事实台账，分为 F 已核实、L 低置信、G 缺口三档。去重键为 asOf + 问题，不含轮次 | 程序 |
| P2 发散 | 背靠背作答：每个视角只回答与自己相关的子问题，产出主张卡（立场、理由、引用的事实、证伪信号）、假设，以及概率（如适用） | 议员（视角 = 方法 + 检查清单 + 专属资料；至少一位使用不同的模型家族） |
| P3 议程 | 产出结论清单和分歧清单。分歧按根源分类（见第 3 节），并写出关键分歧点："若 X，则 A，否则 B" | 主持人只输出结构，配对和统计由程序完成 |
| P4 补证 | 事实分歧转成补证题，走三级取证 | 程序 |
| P5 交锋 | 针对分歧点做配对质询（A 质询 B 的原文，B 回应）；**共识也要被质询**，由红队攻击主要共识（"如果它错了，最可能错在哪"） | 议员 |
| P6 再估 | 匿名展示全体的分布、交锋原文和最新底稿，议员给出终版立场和概率，并说明改了什么、为什么 | 议员 |
| 判停 | 没有新论点，且每条分歧都已被裁决或已找到关键分歧点，才收尾；最多 2 轮 | 程序 |
| P7 收尾 | 程序冻结结论对象，主持人只读取该对象，生成报告；所有输出都过数字闸门 | 程序 + 主持人 |

## 3. 最终产出

1. **结论清单**：每条结论标明状态（多方论证通过 / 有分歧 / 证据不足），附上支撑理由、它扛住了哪些质询、引用了哪些事实。
2. **分歧清单**：每条分歧写明双方、分歧类型、关键分歧点、什么证据能裁决、目前状态。分歧类型：
   - **事实分歧**：双方掌握的事实不同。转成补证题，可以裁决。
   - **解读分歧**：事实相同，但权重或因果判断不同。保留双方的推理链，由用户判断。
   - **假设分歧**：对未来的假设不同。转成追踪项，到期验证。
   - **风险偏好分歧**：判断相同，但行动建议不同。
3. **少数派意见**：由程序按固定规则判定，主持人不得删减。
4. **结果区间与概率**：仅限可判定的议题，作为报告中的一节。主评分用 RPS，Brier 为辅。
5. **追踪项**：由证伪信号和假设分歧生成，到期复盘。

## 4. 数字闸门与证据分档（所有输出，包括主持人）

- **F 已核实**：来自东财结构化数据，或 GEN-10 交叉核实通过。正常显示。
- **L 低置信**：只出现在 n8n 低置信资料中。可以使用，显示时标注"〔低置信〕"，其他人也能看到。
- **无来源**：发言中出现，先让模型重写 1 次，仍有则跳过本轮。会议总结、决策卡片、最终结论里出现，重写 1 次后仍有，替换为"[未核验]"。
- **不检查**：日期、轮次、序号、期间、股票代码、指标参数（如 MA20）。
- **三级取证**：东财优先 → n8n GEN-10 → Codex API 打开原文核实。第三级只用于议员作答时引用的 L/G 项，不设预算（用户 2026-10-18 确认）。
- **一律否决**：bridge 忙时回落到普通搜索；把 L 当作 F；跳过复核。

## 5. 同一套流程 + 5 个可替换点

通用议题和股票议题的流程完全相同。差别只在下面这个接口的实现上，流程代码里不出现"如果是股票就……"这类分支。

| 可替换点 | 股票议题 | 通用议题（默认实现） |
|---|---|---|
| 取证来源 | 东财优先，再走 GEN-10 | 直接走 GEN-10 |
| 数字口径规则 | 前复权、单季与累计、归母与合并等 | 基本数值比对 |
| 参照类数据 | 程序根据东财 K 线计算历史分布 | GEN-10 查询，查不到记为缺口 |
| 结果判定 | 收益率区间，到期自动判定 | 叙事情景 + 其他，不自动评分，或人工判定 |
| 默认视角 | 基本面 / 估值 / 资金与技术 / 行业与宏观 / 空方 | 由议题类型模板决定 |

## 6. 可靠性

- 只保留单一路径：审核模式为唯一模式，旧编排删除；所有写入用 epoch CAS。
- 阶段检查点以 (meeting, stage, round, member) 为幂等键，从第一个未完成的步骤恢复。
- 异常时进入 PAUSED 或 BLOCKED，不再 CANCELLED。服务启动时，把所有 RUNNING 状态改为 PAUSED。

## 8. 已知解决不了或暂不解决的问题

- GEN-10 耗时较长：用户已确认暂不优化，以后可以换成其他 API；底层账号池支持多账号。
- 交叉核实通过 ≠ 读过原文：由第三级 Codex 原文核验部分弥补。
- 概率无法事前校准，只能靠到期评分和对照验证来检验。
- 中文写法的数字（如"一百亿"）目前不检查。
- 数字比对仍是"资料中出现过即可"，偏宽松；S3 的事实编号机制会把它收紧。

## 9. 真实冒烟记录

**2026-10-17，会议 92**（宁德时代，2 位 DeepSeek V4 + 1 位 GPT-5.6 Luna）。DeepSeek 网页账号中途掉线（`login_required`），GEN-10 和 DeepSeek 议员都受影响，只有 1 人有效作答。暴露并已修复的程序问题：

- 主持人输出模板里没有 `stock` 字段，模型照模板输出，股票领域实际从未生效。现在领域通过 `issueCardField()` 把字段写进模板。
- 主持人自设"股价涨跌 ±5%"子问题，与程序生成的结果区间题重复且口径不一。股票提示里已禁止；取证题也不再问截至日期尚未发布的数据。
- 模型调用失败被当成"格式不合格"并存为跳过，会议照常收尾。现在：作答环节有效作答仍有 2 人以上时，失败的议员记为"模型调用失败"并跳过，不足 2 人则暂停且不保存，续跑时重问；交锋、红队、再估、分类环节失败一律暂停，续跑时从该步重来。
- 结果题起点写成 asOf（可能是周末）。现在取最近一根日 K 的日期和收盘价，存为 `baseDate`/`baseClose`，供 S7b 到期判定。
- 页面：没发生交锋时不再显示"交锋 1 轮"；展望期文字不再重复交易日数；作答无效的议员列出原因。

待定：v2 收尾时沿用旧机制，从决策卡片生成"继续会议前必需、每日自动刷新"的追踪项（会议 92 生成了 8 条）。放到 S7b 一并重做。

**2026-10-17，会议 93**（同样配置，修复后重跑，用时 27 分钟）。股票领域生效：东财行情类数字与独立重算逐项一致；子问题只拆驱动因素；取证题不再问未发布数据。暴露并已修复：

- 数字闸门把理由里的事实编号（G-2、F-9）读成负数，导致作答被要求重写、再估被丢弃。现在事实编号不参与数字核验。
- 5 年历史 K 线一次失败就放弃，参照类和结果区间整个缺失。现在东财重试一次，再失败改用腾讯前复权日 K，事实来源如实标"腾讯证券"。
- 底稿数字统一保留两位小数，日期去掉时分秒，分位标明"0%为近一年最低"。
- 作答或再估被要求重写时，记录第一次被拒的原因（`rewriteReason`）。
- 缺证据形成的一致：8 道取证题只核实 1 道，全员选了中间项。现在，如果一条结论的支持理由有一半以上没有引用任何 F/L 事实，就标为"证据不足的共识"，结论文字和页面都会写明。

**2026-10-18，会议 94**（修复后第三次重跑，用时 36 分钟）。结果区间（σ 17.88%，±9%/±27%，起点 10-16 收盘价 277.00）与独立重算一致；东财历史 K 线连续失败后改用腾讯（最多 640 根，来源如实标注）；出现真分歧，交锋后技术分析师改判 Q3、Q4 并写明原因。暴露并已修复：
